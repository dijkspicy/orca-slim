# Spec Delta

## Purpose

让用户在一个应用内管理多个仓库与文件夹工作区，支持分组、排序与磁盘占用分析，并在重启后恢复本地多项目状态。

## ADDED Requirements

### Requirement: 多仓库注册

系统 SHALL 允许添加多个仓库（克隆、新建、或以现有文件夹接入），并 SHALL 在同一界面中同时呈现它们。

#### Scenario: 添加第二个仓库

- **WHEN** 用户添加一个仓库
- **THEN** 系统将其登记并显示在侧栏，且不隐藏先前已登记的仓库

#### Scenario: 移除仓库

- **WHEN** 用户移除一个已登记的仓库
- **THEN** 系统将其从列表移除，且不删除磁盘上的仓库目录

### Requirement: 文件夹工作区

系统 SHALL 支持将非 Git 目录登记为工作区，并 SHALL 在该工作区中提供终端与文件访问。

#### Scenario: 以文件夹创建工作区

- **WHEN** 用户选择一个非 Git 目录作为工作区
- **THEN** 系统登记该工作区并允许在其中打开终端与浏览文件

#### Scenario: 非 Git 工作区不提供 Git 面板

- **WHEN** 当前工作区是非 Git 目录
- **THEN** 系统不显示依赖 Git 仓库的源控制操作

### Requirement: 项目分组与排序

系统 SHALL 支持将仓库分组，并 SHALL 支持对分组与仓库进行手动排序。

#### Scenario: 分组与排序持久化

- **WHEN** 用户将仓库分组并调整顺序后重启应用
- **THEN** 分组与顺序保持不变

### Requirement: 磁盘空间分析

系统 SHALL 报告各工作区的磁盘占用，并 SHALL 允许用户据此选择清理对象。

#### Scenario: 查看占用并清理

- **WHEN** 用户打开磁盘空间视图
- **THEN** 系统按工作区列出占用大小，且用户可选择一个工作区执行清理

### Requirement: 本地多项目状态持久化

系统 SHALL 在重启后恢复仓库、分组、文件夹工作区与其元数据。移除云端账号能力 SHALL NOT 破坏本地多项目状态。

#### Scenario: 重启后恢复

- **WHEN** 应用在登记了多个仓库与文件夹工作区后重启
- **THEN** 仓库、分组与工作区列表恢复，且无需重新添加

#### Scenario: 旧版本状态仍可载入

- **WHEN** 应用载入一份由裁剪前版本写入、且含已移除功能字段的持久化状态
- **THEN** 系统忽略未知字段并正常载入本地多项目状态，而不是拒绝启动或丢弃全部状态

### Requirement: 主机范围限于本地与 WSL

系统 SHALL 仅登记本地与 WSL 主机上的仓库，且 SHALL NOT 登记远程、配对 runtime 或临时虚拟机上的仓库。

#### Scenario: 无远程主机登记

- **WHEN** 用户添加仓库
- **THEN** 可选主机仅为本地与 WSL 发行版
